# Architecture

Captylo is a single macOS app target plus a unit-test target. Everything is built from `project.yml` with XcodeGen. The old app it replaces (a VoiceInk fork) is only a reference: its behaviour was mapped into port notes that the owner keeps outside this repo. This file records the decisions that override them.

**Szpak (fork of Captylo 1.0.17).** No server of ours: no account, no Pro, no relay, no cloud transcription, no update feed (docs/PRD.md). Transcription is local Whisper. Every AI request goes through one seam, `AIRouteProviding` (`Enhancement/AIRoute.swift`): a request names its `AIRole` (`.correction`, the small model: "Czyszczenie", note titles, meeting transcript fixes; `.features`, the stronger model: every other mode, custom prompts, "Przetwórz przez AI", the style profile, meeting notes and "Zapytaj") and gets an `AIRoute` (an OpenAI-compatible `ChatCompletionsClient`, a key, a model id, `kind` local or cloud) or nil, which means no AI right now and the raw text stays. `AppState` wires `AIRoleRouteProvider`: per request it reads where the role runs (`AIRoleRouting`: the Mac's default plan by its memory, `HardwareProfile.plan`, unless the user picked a model per role in Modele) and asks `LocalAIRouteProvider` (the Bielik model server of `Captylo/LocalAI/`, llama-server on 127.0.0.1) or `CloudAIRouteProvider` ("Bielik w chmurze": Bielik 11B in CloudFerro Sherlock on the user's own key, off by default). History keeps `AIRoute.model` as the model name (the local model id, e.g. `bielik-1.5b-v3-q8`).

## Decisions (override the brief where they differ)

| Topic | Decision |
|---|---|
| Deployment target | macOS 14.4, arm64. Liquid Glass behind `#available(macOS 26, *)`, `.ultraThinMaterial` + 0.5 pt white stroke fallback. No `Synchronization` module (needs 15): use `OSAllocatedUnfairLock` for shared mutable state on audio paths. |
| Speech engines | Local Whisper large-v3-turbo via WhisperKit 1.1.0 (argmax-oss-swift, MIT; variant `openai_whisper-large-v3-v20240930`, full precision, ~1.6 GB in `<data>/WhisperModels`, Core ML on the Neural Engine). Nothing else: there is no cloud transcription (`STTEngine` has only `.local`; the setting stays so the debug flags and the seam keep their shape). Chosen on 2026-10-02 over Parakeet TDT 0.6b v3 after a benchmark on a real 15 min Polish meeting through the meeting pipeline: WER against the cloud 31.4 % vs 37.7 %, substituted words 105 vs 152, English/Spanish insertions on backchannels 0 vs 66 (Parakeet cannot be forced to Polish; Whisper takes the language code). Decoding: language forced, no first-token log-prob threshold (a low first token ends the segment empty and leaves it to the random temperature fallback; utterances cut mid-sentence vanished), no no-speech skip on final passes (the audio is known to hold speech; a near-silent dictation that comes back as only "Dziękuję." / "Thank you." is dropped by `TranscriptionRouter.filterHallucination`), WhisperKit's other thresholds as shipped. Deleting the model goes through `WhisperEngine.deleteModel()`, which refuses new loads, waits for a running load and pass, then unloads and removes the files. The 626 MB palettized variant lost (131 vs 109 substitutions), Cohere Transcribe hallucinated on silence. FluidAudio 0.17.4 stays for the meeting VAD and diarization; earlier versions' Parakeet folder is only offered for removal in Modele. |
| AI routes | One seam, `AIRouteProviding.route(for: AIRole, timeout:)` (nil = no AI), `prewarm(_:)` (called at hotkey-down with the active mode's role: `.correction` for "Czyszczenie", `.features` for any other mode) and `withRoute(for:timeout:_:)`, which holds the route while a long call runs (the meeting AI: a local server is never stopped for idleness mid-request, `LocalAIService.withEndpoint`; the default implementation just looks the route up). **Where a role runs** (`AIRoleRouting`, pure; `AppState` keeps a lock-protected snapshot the routes read on every request and feeds `roleModels` to `LocalAIService.setRoleModels` live): a user pick in Modele > Zaawansowane (`AppSettings.aiCorrectionModel` / `aiFeaturesModel`, keys `ai.model.correction` / `ai.model.features`, a catalog id or `cloud`; nothing stored = "Zalecany") wins; otherwise 16 GB and more run correction on Bielik 1.5B and the AI features on Bielik Minitron 7B, under 16 GB correction on 1.5B and the AI features `.cloudOrLocal` (the cloud while it is on with a key, else 1.5B, decided per request). `AIRoleRouteProvider`: a local role asks only the local provider (a missing model = no route, never a silent cloud fallback), a cloud role only the cloud provider (off or no key = no route), `.cloudOrLocal` the cloud first. `LocalAIRouteProvider` maps `AIRole` onto `LocalRole` and turns `LocalAIService.endpoint(for:timeout:)` into `AIRoute(client: ChatCompletionsClient(baseURL: endpoint.baseURL), key: endpoint.token, model: endpoint.modelID, kind: .local)`. `ChatCompletionsClient` builds `POST {baseURL}/chat/completions` with `Authorization: Bearer <key>` (none for an empty key), a full `messages` array (system, few-shot user / assistant pairs, user), `max_tokens` and an optional `temperature` (0 on the dictation path), and parses `choices[0].message.content` and `finish_reason`; errors are `ChatCompletionsError`. `CloudAIRouteProvider` ("Bielik w chmurze", Modele > Zaawansowane): only while `AppSettings.cloudAIEnabled` is on (off by default) and a key is saved in the Keychain (`KeyStore.Account.cloudFerroSherlock`, the only Keychain item); base URL `https://api-sherlock.cloudferro.com/openai/v1/`, model `AppSettings.cloudAIModel` (default `Bielik-11B-v3.0-Instruct`, from CloudFerro's Sherlock docs), both roles; prewarm is `GET {base}/models` debounced by `Prewarmer`; "Testuj połączenie" is a one-token chat with the typed key and model. `AppState` wires the providers in one marked place ("AI routes"). |
| AI cleanup | `Enhancer` asks the route for the job's role within the job's deadline (the lookup counts against it; a provider that overruns fails the call with `.deadline`, and a nil route that came only at the deadline, a local server still starting, is a timeout, not "Brak modelu AI"), one retry on connection loss when 0.8 s remain, and keeps the raw text on any failure (`.skipped(.noKey)` without a route). **A cleanup job** (kind `.cleanup`, PRD 7.2) sends `CleanupPrompt.messages`: the Polish correction prompt (`CleanupPrompt.defaultTemplate`, F0; a user's own cleanup template replaces only this system text), two invented few-shot user / assistant pairs, then the transcript, every user turn wrapped as `<tekst>\n...\n</tekst>`; `temperature 0`, `max_tokens` = input words x 3 + 32. Learned "heard -> meant" pairs are appended (in Polish for cleanup), the style profile is not (it pushes a small model to rewrite; rewrite modes keep it). The answer is stripped of reasoning blocks and echoed tags, then goes through `CorrectionGuard.apply` with the job's vocabulary (dictionary terms plus the meant side of learned pairs, `CleanupPrompt.guardVocabulary`) and `CorrectionSpelling` (the system spell checker on the main actor, injectable for tests): the merged text is the result, a rejection is `.failed(.rejected(...))` ("Odrzucono: zbyt duża zmiana treści" for low word similarity) and the raw text is pasted. A rewrite job sends the system prompt and the bare transcript. **Deadline** (PRD 5, both routes): the job's own limit (the mode's "Limit czasu", or the enhancer's 3 s / 15 s) stretched to `LocalDeadline.limit(for:input:)` (cleanup 1 s + words x 0.04 s x 1.5, modes 10 s + words x 0.23 s x 1.5) and capped at 15 s (cleanup) / 30 s (modes); `Enhancer.deadline(for:input:fallback:adaptive:)`, on for both app enhancers. The dictation enhancer reports `LocalUsageEvent`s (accepted / rejected corrections with their time, mode uses by built-in key or mode id, timeouts). History keeps the route's model. The meeting AI (`MeetingChat`) sends the open Polish instructions (`MeetingAIInstructions.system(for:)` -> `MeetingPrompts`) as the system message and the data as the user message at temperature 0.2, holding the route for the call (`complete(task:system:user:maxTokens:)`); it has no deadline beyond `HTTP.meetingLLMSession` (10 min idle, 30 min total), since it runs in the background. |
| AI modes ("Tryby AI") | The prompt comes from the active `AIMode` (`AppSettings.aiModes` / `aiActiveModeID`, JSON in `ai.modes`), `ai.enabled` stays the master switch ("Bez AI"). Built-ins (`BuiltInAIModes`, fixed ids): Czyszczenie (the Polish cleanup template, 3 s), Po angielsku (6 s), Uporządkuj myśli (8 s), E-mail (6 s), Lista zadań (6 s). A stored "Czyszczenie" still holding Captylo's English cleanup prompt (`CleanupPrompt.legacyTemplate`) reads as the current default (`AppSettings.upgradingShippedCleanup`). Kind `.cleanup`: skip at 3 words or fewer, the few-shot request and `CorrectionGuard` above (it replaces the old 0.4...2.5 length ratio), cap `min(2048, words x 3 + 32)`. Kind `.rewrite`: any non-empty text, reject only empty or cut off, cap `min(4096, est * 3 + 256)`. The mode's limit (1...20 s) is the floor of the adaptive deadline; `HTTP.llmSession` and `HTTP.fileLLMSession` time out above 30 s, so the Swift race is the real limit. A custom `ai.prompt` from before modes becomes "Mój prompt" (active) until the list is first saved. Every AI dictation stores `enhancementMode` and, when there is no AI text, a short Polish `enhancementNote` (AI off: both nil). "Przetwórz przez AI" (`HistoryActions.reprocessWithAI`) and "Testuj tryb" (`ModeTester`) use `AppState.utilityEnhancer` (file session, 15 s) and never add a `UsageStat`. Roles (`AIMode.role`): the built-in "Czyszczenie" is `.correction`, every other mode `.features`; "Przetwórz przez AI" always uses `.features`. |
| Audio capture | `AVAudioEngine` input tap, device chosen with `inputNode.auAudioUnit.setDeviceID(_:)` before start. One persistent `AVAudioConverter` to 16 kHz mono Float32. WAV written with `AVAudioFile` (Int16, 16 kHz, mono). Stop = remove tap, stop engine, close file, then read. No raw AUHAL, no ring buffer. |
| Hotkeys | `CGEventTap` on its own thread, hybrid mode only (tap < 0.5 s latches, hold >= 0.5 s is push-to-talk), default Right Command (`Hotkey.defaultHotkey`; Captylo uses Right Option), presets Right Option and Fn, custom combos via recorder. The global combos (`GlobalShortcut`) are ⌃⌥⇧M (meeting), ⌃⌥⇧N (voice note) and ⌃⌥⇧P ("Popraw"), not Captylo's ⌃⌥⌘, so both apps keep their shortcuts. Esc twice cancels while the widget is visible. Accidental-start guard for Right Option + letter. |
| Live transcript card | Lives in the expanded widget (mockups 03/04), which opens while the pointer rests on the widget. The compact state is exactly mockup 01 (orb, free-floating waveform, timer) and shows no text, so a take never grows a card over the app being dictated into. Both states are bottom-anchored near the screen edge. |
| Output | Pasteboard + synthetic Cmd+V from a `.privateState` event source, stamped with `eventSourceUserData = 0x56544332` so our own tap ignores it. Clipboard restored after 2 s if `changeCount` is unchanged. Paste failure = text stays on the clipboard + toast. |
| Identity | Product Szpak: bundle id `pl.craftweb.szpak` (tests `pl.craftweb.szpak.tests`), `Szpak.app` with executable `Szpak`, data in `~/Library/Application Support/Szpak/`, Keychain service and `os.Logger` subsystem `pl.craftweb.szpak`, URL scheme `szpak` (registered, links are logged and ignored), MCP server name `szpak`. Three places hold it: `Captylo/App/AppIdentity.swift`, the `APP_*` build settings in `project.yml` and the variables at the top of the `Makefile`; `AppIdentityTests` checks they agree and that nothing collides with Captylo. The Swift module and the Xcode project stay "Captylo"; the word "Captylo" in UI strings is a later pass. |
| Data | SwiftData at `~/Library/Application Support/Szpak/Captylo.store` (configuration `Captylo`, `cloudKitDatabase: .none`), `dictionary.json` next to it, `Recordings/<id>.wav`, voice notes in `Notes/<id>.wav`, `device.json` (this installation's id, see "Notatki"), the search index `Search.sqlite` for meetings and notes (our own SQLite file, rebuildable from the store at any time, see "Search" under Spotkania). `UsageStat` is append-only and drives the dashboard; deleting history never changes totals. Schema is import-friendly for the old store (phase 2, not built now). |
| UI language | Polish source strings, English translations in `Captylo/Resources/Localizable.xcstrings` (Info.plist strings in `InfoPlist.xcstrings`). Numbers and dates follow the UI language through `AppLocale`. Mockup strings are used verbatim. The UI language follows macOS unless "Język aplikacji" (Ustawienia > Aplikacja, or "Polski / English" on the welcome screen) picks one: `AppLanguage` writes the app's own `AppleLanguages` (what System Settings > Language & Region > Applications writes; `.system` removes it), and `AppRelauncher` restarts the app, never while a dictation or meeting records (`AppState.isRecordingAnything`) or in the design preview. A running process keeps its language. `CFBundleDevelopmentRegion` must stay `pl`: `pl.lproj` has no `Localizable.strings` (Polish keys are the text), so with `en` a Polish UI reads the English table; a Mac with neither language gets Polish. |
| Signing | Xcode builds ad-hoc (`CODE_SIGN_IDENTITY=-`), hardened runtime on, sandbox off. `make release` then re-signs `~/Downloads/Captylo.app` with the local self-signed identity "Captylo Dev" (`make sign`, created once by `scripts/setup-signing.sh` in its own keychain `captylo-dev.keychain-db`), so the designated requirement is certificate-based and Microphone/Accessibility grants survive rebuilds. `make sign` goes through `scripts/sign-app.sh`, which signs inside-out (XPC services, helper apps and helper executables inside frameworks, then frameworks and dylibs, then helper executables in `Contents/MacOS` and `Contents/Helpers`, such as a bundled model server, then the app). Development signatures (Captylo Dev, or ad-hoc when that identity is missing) also add `com.apple.security.cs.disable-library-validation` to a copy of the entitlements made at sign time in `.local-build/`: library validation compares Team IDs and neither a self-signed nor an ad-hoc signature has one, so an embedded framework would be refused by dyld. A Developer ID release signs with `Captylo.entitlements` unchanged. Under hardened runtime every protected resource also needs its entitlement in `project.yml` (`device.audio-input`, `personal-information.calendars`): without it macOS denies the request silently, with no prompt, and the status stays "not determined". Without that identity builds stay ad-hoc and grants are per build hash (`make reset-tcc`). Three signatures, by purpose: ad-hoc (`make build`, `make test`), "Captylo Dev" (local `make release` / `make install`, and `make dist-dry`), and "Developer ID Application" for public releases only (`make dist`: `scripts/release.sh` signs inside-out with hardened runtime and a timestamp, notarizes the zipped app and then the DMG with the notarytool Keychain profile `captylo-notary` and staples both; the DMG goes to a GitHub release by hand; owner steps in [release.md](release.md)). The Developer ID build has a different designated requirement from "Captylo Dev", so on a Mac that ran a development build macOS asks for Microphone, Accessibility, Calendar and System Audio once more; no migration. |
| Self-learning | Local only, no server (Honcho and similar were rejected: privacy and the Free plan). Switch `learning.enabled` ("Ucz się z moich poprawek", default on). Sources: words spelled out loud (`SpellingDetector`, before `TextProcessor`; a take that is only a spelling, "Pisane J-E-V", is not pasted and corrects the closest word of the previous take) and edits of pasted text read back through Accessibility (`EditWatcher`: only the pasted field, polled twice a second and every 100 ms for 3 s after the text or the selection moved, so a fix typed right before Enter is still read; a take dictated over 1...3 words selected inside a paste watched in the last 2 min is learned as a pair, selection -> new take; when our text leaves the field (a chat message sent, the box cleared) the watch ends with the last text that still held it; ends when the field loses focus (its own `AXFocused` first) or the app changes, on the next take, 90 s idle or 10 min; never secure fields, password managers or terminals; `start()` calls `prepare()`, which sets `AXManualAccessibility` on the frontmost app and, for Chrome-family browsers, `AXEnhancedUserInterface`, so the tree is built by paste time; every AX call runs off the main actor behind a deadline (`EditWatcher.offMain`: 150 ms for the snapshot before Cmd+V, else no watch; 2 s while watching) on top of a 0.5 s AX messaging timeout; browser results in docs/reference/ax-coverage.md). `CorrectionLearner` (pure) keeps 1...3-word term fixes, sends bigger edits to style samples and drops rewrites (< 50 % words kept) and text typed after the paste; a paste of at most 3 words retyped as a whole ("supa bejs" -> "Supabase") is judged as one change, not a rewrite. A pair is learned at the first sighting (the owner's workflow: select the word, retype it, done; `SelfLearning.threshold` = 1, the Cofnij toast is the safety net): the correct form joins the vocabulary, and a replacement rule is added only when the misheard side is not a real word (`NSSpellChecker` pl + en), otherwise it is an AI hint. Every lesson shows "Zapamiętałem: a → B [Cofnij]"; undo removes what it added and blocks the pair; correcting a learned form back drops the rule, twice forgets it. Style: every 8 samples the utility enhancer (15 s, only with AI on) distills a profile of at most 700 characters, editable in Słownik; the prompt gets the hints, the profile and the target app name. Memory in `learning.json` next to the dictionary (so test host and design preview use temp copies). Settings also hold `learning.notifications` (the toasts) and `learning.excludedApps` (bundle ids picked as .app in Ustawienia > Nauka, on top of the built-in list). Every watched paste, edited or not, adds to daily `editStats`; Pulpit shows "Poprawki/100 słów" over 14 days once there are 50 watched words. **"Popraw"** (`ManualCorrection`): the user selects text in any app and presses ⌃⌥⇧P (`GlobalShortcut.correction`, setting `learning.fixShortcut`, on by default, Ustawienia > Podstawowe > Nauka) or picks right click > Usługi > "Popraw w Captylo" (`NSServices` in project.yml, message `fixSelection`, `CorrectionServiceProvider` set as `NSApp.servicesProvider` in `startServices()`; Electron apps have no Services menu, so the shortcut is the universal path). `SelectionReader` reads the selection through `AXSelectedText` and falls back to a synthetic Cmd+C (`KeySynth.copyCommand`, the clipboard restored right after). `CorrectionPanel` is a borderless `.nonactivatingPanel` that can become key, so the source app stays active and keeps its selection; its line under the field shows `SelfLearning.preview` live ("Zapamiętam: a → B", "jako podpowiedź dla AI", "to zmiana treści"). Enter pastes the fix over the selection (`TextOutput.deliver`, trailing space only when the selection ended with one) and calls `learnManual`: `CorrectionLearner.manual` trusts the user more than the watcher (ordinary words that sound alike count, "może" → "morze", but another form of the same word, "piątek" → "piątku", is grammar; a case-only fix needs a non-word or inner capitals), learns at once, unblocks a pair undone before, replaces a reversed lesson and always shows the toast. **"Ostatnio zauważone"** (`ObservedPanel` on Słownik): every decision lands in `learning.json` `observations` (40 kept, fragments cut to 80 characters, local only) with a `LearningSkipReason` (rewrite, longChange, sentenceCase, ordinaryWords, punctuation, blocked, alreadyKnown, unreadable); a field the watcher could not read is listed once per app every 6 h, and a blocked pair has "Odblokuj". The vocabulary does not reach the local model: a Whisper prompt with the vocabulary (3 or 11 terms) fixed one surname on the owner's meeting but dropped 2-3 times more words (168-209 deletions vs 63) and ran slower, so the local model gets no prompt and replacement rules stay the way to fix its spelling. |
| Updates | None in the app: no update feed, no automatic check, no network call for it. New versions come by hand from GitHub releases ([release.md](release.md)). The Ustawienia footer shows the version (`AppVersion.versionLine`, "Wersja 1.0.0 (142)"). |
| Network | Only two destinations, both on the user's action: huggingface.co when a model is downloaded (the Whisper model; the Bielik models with `Captylo/LocalAI`) and CloudFerro Sherlock while "Bielik w chmurze" is on. No telemetry, no server of ours. Calendar, MCP and everything else stay on the Mac. |
| Dependencies | FluidAudio and WhisperKit. Apple frameworks otherwise, plus the system `libsqlite3` for the meeting search index (`import SQLite3`, autolinked, so `project.yml` lists nothing; FTS5 and the `trigram` tokenizer (SQLite 3.34+) are compiled into the system library, 3.51 on the macOS 26 build Mac; `load_extension` is off, so no extensions). A system library needs no `NOTICE.md` entry. |

Ownership rule: a module talks to another only through the protocols in `Dictation/DictationTypes.swift` and the concrete types listed in the brief section 4. `AppState` builds every service once in `init` (safe for the headless debug commands) and injects them; `startServices()` adds the launch behaviour of a GUI run (tap install on the Accessibility grant, audio and local model prewarm, the meeting voice detector prewarm, retention, the calendar refresh loop and reminders, call detection, settings observers). No singletons except `Log`. Shell hooks the controller needs (open Modele, open a Settings pane, bump stats) are closures in `DictationEnvironment`, so `Dictation/` never imports the window layer. `AppState` also owns the `FileTranscriptionQueue`: Finder "Otwórz za pomocą" files are stashed in `pendingOpenURLs` until `startServices()` has created the data directories, then fed to the queue and the main window opens on Transkrypcja pliku; the drop zone feeds the same queue. `AudioDecoder` accepts wav, mp3, m4a, aiff, aac, flac, caf, mp4, mov and Ogg/Opus voice notes (ogg, opus, oga); a file without a known name extension (messenger voice notes saved as `voice_<date>`) is recognised by its first 12 bytes (`sniffedExtension`). `AVAssetReader` decodes first; Ogg goes straight to `AVAudioFile` + `AVAudioConverter`, since `AVURLAsset` cannot open it, and the same path is the fallback when `AVAssetReader` fails. Ogg relies on Core Audio (verified on macOS 26); where the system cannot read it the row says "Ten format nie jest obsługiwany przez macOS na tym komputerze." The picker also allows `.data` so extensionless files can be chosen; Finder "Otwórz za pomocą" is registered for audio, movie and the Ogg types only.

## Dictation flow

1. `HotkeyTap` (background thread) → `HotkeyController` (MainActor) decides tap vs hold → `DictationController.start()`.
2. `start()`: mic permission check, device resolve, `AudioCapture.start` (samples into `SampleBuffer`, WAV to disk), after 150 ms play the start sound, show the widget, mute system output; `LivePreview` re-transcribes the last 15 s every 1.5 s while recording (a Whisper pass takes 0.7-0.9 s; a preview never waits for the model and stops decoding as soon as a final pass is waiting).
3. `stop()`: stop capture, `TranscriptionRouter` (local Whisper full pass; while the model is still being prepared, i.e. the first load compiling it for the Neural Engine, which also happens after macOS purged the app's caches on a full disk, a pass waits at most `defaultModelWait` (90 s) before `DictationError.modelPreparing` instead of hanging on "Transkrybuję"; `start()` says so at once, and warns once per 10 minutes when the data volume has less than 1 GB free, `DiskSpace`), `SpellingDetector` (words spelled out loud), `TextProcessor` (tags, fillers, whitespace, paragraphs, replacements), optional `Enhancer` (the active mode's role on `AIRouteProviding`, the mode's deadline, prompt with the learned hints and style), stop sound, hide widget, `EditWatcher.willPaste`, `TextOutput.deliver` (pasteboard + Cmd+V + restore), `EditWatcher.didPaste`, then `Database.save`, bump `statsVersion` and learn the spelled words. `start()` of the next take flushes the watcher first.
4. `cancel()` (Esc twice, or accidental-start guard) aborts capture, deletes the WAV, hides the widget, saves nothing.

Timing budget on Apple Silicon: key-up to paste <= 400 ms local; with AI cleanup p50 ~1 s, never more than deadline + 0.3 s.

## Spotkania (notetaker)

Records a call on the Mac without a bot: the mic as "Ja" and everything the Mac plays as "Rozmówcy", two separate tracks, transcribed live and locally with the Whisper model. Separate from the dictation path: the dictation hotkey keeps working during a meeting and both transcripts land.

**Layout.** Logic in `Captylo/Meetings/` (recorder, transcriber, feeds, echo filter, export, retention, launch resume), with `Audio/` (sources, track files, watchdog, Core Audio process list, voice processing), `Speakers/` (diarization), `AI/` (templates, notes and "Zapytaj"), `Search/` (the full-text index and the search results), `MCP/` (the read-only MCP server), `Detection/` (call detection) and `Calendar/` (the user's calendar, matching, reminders). Views in `Captylo/UI/Meetings/` (sidebar section "Spotkania": the "Nadchodzące" strip, "Połącz kalendarz" while the calendar is off and not dismissed, or on while macOS has not answered (`CalendarConnectRow`; "Nie teraz" turns the calendar off and sets `meetings.calendarPromptDismissed`; with the calendar on but no full access it explains why and opens System Settings; the text and a line under "Kalendarz" in Ustawienia point Google and Outlook users to macOS Internet Accounts, `CalendarAccess.openInternetAccounts()`, since EventKit reads every account added there), search with hit lines, list, live view, details with "Notatki", "Transkrypt", "Notatki AI" and "Zapytaj", the "Zapytaj wszystkie spotkania" panel, settings panel). Storage in `Data/MeetingModels.swift` (`Meeting`, `MeetingSegment`) and `Data/Database+Meetings.swift`. One type per file; tests in `CaptyloTests/Meeting*Tests.swift` with fakes in `MeetingFakes.swift`.

**Data flow.**

1. `MeetingRecorder` (`@MainActor @Observable`, one meeting at a time) refuses to start without the speech model on disk (`MeetingEnvironment.speechModelReady`: every pass would fail and the meeting would end with no transcript; Spotkania shows "Brakuje modelu mowy" with "Otwórz Modele"), then creates the `Meeting` row (`start(title:appName:event:)`: an explicit event, or with no title the event `MeetingEnvironment.currentEvent()` matches now, gives the title, `calendarEventID`, `participants` and the app name from its call link; a default "Spotkanie w Zoom, ..." title only without an event), suppresses `SystemMute` for the whole meeting (a dictation take never mutes the call) and starts the sources on its own serial queue: `MeetingMicCapture` (default input on its own `AVAudioEngine`, rebuilt on device changes, holes filled with silence; `MeetingEnvironment.makeMic` runs on the main actor at start, so it reads "Redukcja echa" then) first, then `SystemAudioTap` (global Core Audio process tap excluding Captylo, private aggregate device, converted to 16 kHz mono Float32). "Nagraj spotkanie" (menu bar, Spotkania, the detector) always opens Spotkania first: a meeting never records without its live bar and the menu bar state.
2. Each source feeds a `MeetingTrackFeed`, which keeps the track on the meeting clock (pads the start and rebuild holes) and hands every buffer, under one lock, to a `TrackFileWriter` (`me.caf` / `them.caf`, 16 kHz mono Int16, appended as recorded) and to the `MeetingTranscriber` actor.
3. `MeetingTranscriber`: per track, 4096-sample chunks -> Silero VAD (shared `SpeechDetectorCache`) -> utterances of at most 14 s (28 s was tried: longer mic utterances mixed the user's words with echo of the other side, the segment-level echo check dropped them, and Whisper substituted more words too) -> timed Whisper pass (word times, `WordTimings`) -> `MeetingSegment` saved right away. Partials go through `previewText`, which returns "" while the model is busy, so they never hold up a final. Partials (the grey line) about once per second of speech. Memory per track is one open utterance, never the whole meeting. When the VAD cannot load or a pass throws (no or a broken model), the transcriber sends `MeetingLiveUpdate.problem` and the live bar warns that no transcript is being made until it works again. The VAD (about 1 MB, downloaded once by FluidAudio) is fetched ahead of the first meeting: `SpeechDetectorStatus` (`AppState.speechDetectorStatus`, states missing / loading / ready / failed) calls `SpeechDetectorCache.prewarm()` after a successful local model download (`LocalModelStore.onDownloaded`) and in `startServices()` after the local model prewarm when the model is installed; Modele and the onboarding model step show it under the model status as `SpeechDetectorStatusLine` ("Wykrywanie mowy do spotkań: gotowe" / "pobieram..." / "nie pobrano (...)", nothing while missing). A failure is only logged and shown there; a meeting started meanwhile loads the detector itself.
4. `stop()` closes the sources and files, `finish()` marks echo between the tracks (`EchoFilter`), the row gets its length and goes to "processing", and the recorder is idle again (a back-to-back call can be recorded at once; the detector asks about a call that started while the last meeting finished once the recorder is idle). The post-processors (`MeetingPostProcessing`) then run in the background, one meeting at a time in stop order: `SpeakerLabelProcessor` (macOS 15+), `MeetingCorrectionProcessor` ("Poprawiaj transkrypt przez AI"), `MeetingNotesProcessor` (AI notes; without an AI route the row keeps the reason), `MeetingRetention` (last, it may delete the audio the first ones read). Then "completed" and `processedCount` bumps, so Spotkania reloads the labels and the notes. Meanwhile the list says "Przetwarzam" and "Notatki AI" says "Piszę notatki...".
5. Crash or quit: segments saved so far stay, the CAF files stay readable (`abortForTermination` closes them on a normal quit); `recoverInterruptedMeetings()` marks the row "Przerwane" at the next launch, marks its echo (the stop never did) and gives it a length (the longer of the track files and the last segment). A quit while the post-processors still run leaves the row "processing": the transcript, echo marks and length were saved by the stop, only the extras were cut. `Database.markInterruptedMeetings` returns a `MeetingRecovery` (`interrupted` plus `resumed`, the "processing" rows marked "completed" in stop order) and `resumeProcessing(ids:)` queues `MeetingEnvironment.resumeProcessors` on the same serial chain as a stop, with `reopen`: the row reads "processing" again, then "completed" and `processedCount` bumps. The resume list holds only the AI steps, each behind a `MeetingResumeStep` that skips work already on the row (`MeetingCorrectionProcessor` when `transcriptAIModel` is nil, `MeetingNotesProcessor` when `summary` is nil; their own setting gates still apply), then `MeetingRetention`; never the diarizer (a crash there must not repeat at every launch). A crash during the resume leaves finished steps done, so the next launch runs only what is still missing. "Napisz notatki" and "Popraw" keep working on an interrupted row.

**System audio checks.** A denied grant and the long-session HAL zero-buffer bug both deliver exact zeros with `noErr` everywhere. `SilenceWatchdog` sees zeros while another process plays output (`CoreAudioProcesses.anyOtherProcessPlaying()`); `SystemTrackWatch` decides. Before any audio: the tap is rebuilt after 8 s of zeros, then 12 s, 20 s, 40 s and every 120 s (a tap made before the first grant can stay on zeros after "Allow"), and only after 30 s does the live bar say "Na razie nie słyszę rozmówców..." with the way to System Settings (a call often starts in silence). After audio: quiet tap rebuilds (30 s, 30 s, 60 s, then every 120 s of zeros) and a gap ("przerwa w nagraniu") when a rebuild brought the audio back. Ustawienia > Spotkania > "Sprawdź" runs the tap for 2 s (`SystemAudioCheck`). The headphones hint shows while the default output is the built-in speakers.

**Permissions.** Microphone (existing) plus "System Audio Recording Only" (`NSAudioCaptureUsageDescription` in `project.yml`, English in `InfoPlist.xcstrings`; the prompt appears at the first `AudioDeviceStart` of the tap, there is no public API to ask or query it; deep link `Privacy_AudioCapture`). No Screen Recording, no ScreenCaptureKit. Meeting detection reads browser window and tab titles through the Accessibility grant the hotkey already needs. Calendar (optional, Free): full access to events (`NSCalendarsFullAccessUsageDescription` in `project.yml` + `InfoPlist.xcstrings`, asked with `requestFullAccessToEvents()` the first time "Kalendarz" is switched on; deep link `Privacy_Calendars`). On macOS 14 "Add only" in another app's prompt leaves Captylo `writeOnly`, which is explained like a denial, never treated as granted.

**Diarization.** "Mówca 1/2/3" on the "Rozmówcy" track only on macOS 15+: FluidAudio's `OfflineDiarizerManager` crashes on macOS 14 (FluidAudio #878, an Apple BNNS bug fixed in 15). It reads the closed `them.caf`; one remote voice or any failure keeps "Rozmówcy".

**AI notes.** `MeetingSummarizer` writes the notes as `MeetingAITask.notes(templateID:)` on the features model (`AIRole.features`), on `HTTP.meetingLLMSession` (10 min idle, 30 min total), through `MeetingNotesWriter`: one call when the instructions (`MeetingPrompts.notesSystem`) and the data fit the 20k-token input budget (`TranscriptChunker`, the features server runs with `-c 24576`), otherwise the notes of each part, one after another, then merge calls (`MeetingPrompts.notesMergeSystem`); every answer goes through `CitationNormalizer`. A run of several calls reports "Piszę notatki, krok N z M" in "Notatki AI" (`MeetingNotesProcessor.onProgress` -> `MeetingNotesRuns.progress`, also after a meeting). Measured with Minitron: about 35-60 s for a short meeting, about 2 min for 45 min. The data carries the title and, when the meeting came from a calendar event, a "Uczestnicy: ..." line (`MeetingNotesPrompt.user`), so the names are spelled right; it leaves the Mac only when the route is the cloud one ("Bielik w chmurze"). The answer is Markdown with the sections `MeetingNotesDocument` reads. The template (`BuiltInMeetingTemplates`: Ogólne, 1:1, Standup, Rozmowa z klientem, Rekrutacja, Wykład / webinar; the app holds id, name and title keywords, the instructions what each one focuses on) is picked from the title as it is when the notes are written (the title is editable in the details header, also while recording, `MeetingTitleEditor`; a default "Spotkanie w Zoom, ..." title picks Ogólne) or by the user ("Wygeneruj ponownie", `MeetingNotesRuns`). Citations `[mm:ss]` play the track at that moment.

**Transcript.** The live local transcript is the meeting's transcript; there is no cloud pass after the meeting. `Meeting.transcriptModel` stays in the schema (additive rule) but is never set.

**AI fixes of the transcript.** `MeetingCorrectionProcessor` with `MeetingTranscriptCorrector`: the lines (no echo) go in batches of up to 80 lines / 7000 characters, one batch at a time (a local server answers one request at a time), as `n|text` with the title and a glossary (dictionary + speaker names + the calendar participants, `MeetingTranscriptCorrector.glossary`) under `MeetingPrompts.correctionSystem`; the correction model (`MeetingAITask.transcriptCorrection`, `AIRole.correction`) answers the same numbered lines (`MeetingCorrectionPrompt` builds the data and parses the answer). A line is only swapped for its fixed version, never merged, split or dropped, only when it keeps about the same number of words and characters, and only when `TranscriptFixGuard.isSafe(original:fixed:glossary:)` accepts it word by word (spelling, diacritics, glossary terms; in trials the 1.5B damaged 62 of 306 clean lines without it, none with it), so a summary, an added sentence or another word loses that line, not the transcript. Each fixed segment keeps `originalText`; "Przywróć transkrypt sprzed poprawek AI" (`Database.restoreOriginalTranscript`) puts it back. Word times are reused when the count matches, otherwise spread over the old span. `MeetingChat` is the shared non-streaming call of the fixes, the AI notes and the asks: the route of the task's role held for the call (`MeetingChat.routeTimeout`, 120 s, since a local server may have to start), the system instructions, the data as the user message, temperature 0.2; no route is `noKey`, a non-2xx status `server(code)`, a timeout `timedOut` (`MeetingSummaryError`). Meetings use the models picked for the roles in Modele.

**Transcript actions.** Above the transcript in the details: where it comes from ("Transkrypt z Maca", "poprawiony przez AI"), the last failure, and the "Popraw" menu (`MeetingTranscriptRuns`): "Popraw przez AI", "Przywróć transkrypt sprzed poprawek AI". Every action that changed the transcript writes the AI notes again with their template when the meeting has notes, so notes and export never describe an older transcript (a meeting without notes stays without them). "Eksportuj" also has "Usuń tylko nagranie" (confirmed; removes the folder, `hasAudio = false`, transcript and notes stay; off while recording, processing or a transcript run).

**Shortcut.** ⌃⌥⇧M (`GlobalShortcut.meeting`, "Skrót ⌃⌥⇧M" in Ustawienia > Spotkania, on by default) starts a meeting (Spotkania opens first) or ends the one that records. `GlobalShortcut` registers it with Carbon `RegisterEventHotKey`: no event tap and no Accessibility, and the press never reaches the focused app. Registered in `startServices()` only (never in the design preview or the test host); the menu bar items show it.

**Calendar (Free).** "Kalendarz" in Ustawienia > Spotkania (`AppSettings.meetingsCalendar`, off by default) names a recording after the calendar event, keeps the participants and reminds before a call. Sources: `CalendarEventSource` is `EventKitSource` in the app (one `EKEventStore`, reads on a utility queue because a big calendar takes hundreds of milliseconds, `EKEvent` never leaves it; `EKEventStoreChanged` as an `AsyncStream`) and `FixedCalendarSource` in the design preview and the test host (`AppStateOverrides.calendarEvents`, so neither ever touches EventKit). `MeetingCalendar` (`@MainActor @Observable`) holds the `CalendarAccess` (notDetermined / fullAccess / writeOnly / denied / restricted, re-read on every refresh because the user can change it in System Settings) and `upcoming`: plain `CalendarEvent` values (id = `eventIdentifier`, title, start, end, calendar title, up to 50 participant names with the organizer first and the user left out, `callApp` from `CallLinkDetector`) from 15 min ago to 12 h ahead, all-day events left out, refreshed every 5 min, on every calendar change and on demand; empty while the setting is off or access is not full, so nothing from the calendar reaches a recording the user did not ask to link. `CallLinkDetector` names the service only for a real link (a host under meet.google.com, zoom.us / zoom.com, teams.microsoft.com / teams.live.com, webex.com, whereby.com, meet.jit.si or any `jitsi` host label, discord.gg / discord.com, slack.com with `/huddle`, facetime.apple.com) in the URL, the location or the notes; the word "Zoom" in a title is not a link. `CalendarEventMatcher.match` picks the event for a recording that starts now: in progress (start <= now < end + 5 min) or starting within 10 min, preferring a call link, then in progress over upcoming, then the most recently started (the soonest among upcoming), then the shorter, then the id; a start without an event (the menu bar, ⌃⌥⇧M, "Nagraj spotkanie") and the detector's offer go through `MeetingCalendar.currentEvent()`, while the upcoming strip and the reminder pass their own event to `start(event:)`. Occurrences of a recurring event share one `eventIdentifier`, so views key on the whole value and the reminder on id + start. UI: Ustawienia > Spotkania has the "Kalendarz" switch (turning it on asks for access when undecided, turning it off only refreshes; denied / restricted / write-only get a red `ToolStatusLine` with "Otwórz Ustawienia systemowe", `CalendarAccess.openSettings()`), and "Przypominaj przed spotkaniem" with "W chwili startu" / 1 / 2 / 5 min (`meetingsCalendarReminder`, `meetingsCalendarReminderMinutes`; other values read as 1), both greyed while the calendar is off. Spotkania shows `UpcomingMeetingsStrip` under the header and in the empty state: at most 3 events that have not ended, soonest first, "Trwa" for one in progress, the time, the title, the service badge, the participants count (`MeetingParticipantsLabel`: "1 osoba", "2-4 osoby", "5+ osób", the names in a tooltip) and "Nagraj" (disabled while a meeting records or starts), which opens Spotkania and starts the recorder on that event. Reminders: `CalendarReminder` (started in `startServices()`, checks every 30 s) shows "Za 1 min: „Budżet Q4” (Meet). Nagrać notatki?" or "Zaczyna się: ..." with "Nagraj" for an event with a call link whose start is within the setting's minutes (up to 60 s past the start), once per occurrence per launch; quiet while a meeting records or starts, and for an event whose call the detector offered within the last 2 min (`MeetingDetector.lastOfferAt`), which silences that occurrence for good; in the other direction the detector skips its offer for a call that starts within 2 min of a reminder while that event still matches (`MeetingDetector.recentReminder`, `CalendarReminder.lastReminderAt`), so one meeting never gets two "Nagrać?" toasts. Events without a call link get no reminder (in-person meetings start by hand). The reminder never starts a recording by itself. Privacy: only access states and counts are logged (`Log.calendar`), never a title or a name, and the participants leave the Mac only inside the AI notes, AI fixes and "Zapytaj" prompts, when those AI features run on "Bielik w chmurze" (or through the MCP server to the assistant the user connected).

**Call detection.** `MeetingDetector` polls `CoreAudioProcesses.usingInput()` every 2 s off the main actor and maps the processes through `MeetingAppCatalog` (Zoom, Teams, Slack, FaceTime, Webex, Discord, Around, Tuple; Chrome, Safari/WebKit, Arc, Edge, Brave, Firefox; each entry has its main bundle ids plus helper prefixes). Browsers count only when a window or tab title names a call service (Meet, Teams, Zoom, Whereby, Jitsi): `BrowserCallWindows` reads the window titles and the tab strip (`AXRadioButton` tabs under an `AXTabGroup`, at most 200 elements per window, the page and lists skipped) and answers `call`, `noCall` or `unknown` (one tab per window, Arc's sidebar, a browser that does not answer); titles are compared, never logged or kept. `DetectionTracker`: a call starts after 5 s of mic use and ends after 45 s without it. Call started while idle: toast "Wygląda na spotkanie w X. Nagrać notatki?" with "Nagraj", or "Wygląda na spotkanie „Budżet Q4” w X..." when a calendar event matches; "Nagraj" opens Spotkania and starts the recorder with that app and event (`recorder.linkedEvent`). A call that started while the last meeting was still finishing is asked about once the recorder is idle. Call end has four signals: (1) 45 s without the mic; (2) the app's process quit (`NSWorkspace.didTerminateApplicationNotification`, only the main bundle id through `MeetingAppCatalog.isMainApp`: Chrome renderers, Teams and WebKit helpers quit mid-call all the time), which ends its call at the next poll; (3) a browser in a call that holds the mic for 30 s (`browserIdleAfter`) while its tab strip shows no call tab (`CallScan.browsersWithoutCallWindow`, only on `noCall`) is dropped from the scan and then waits the usual 45 s (leaving the Meet tab for another tab in the same window is fine: the tab strip still shows Meet; `unknown` browsers keep counting until they release the mic, like M1); (4) the recording's calendar event over for more than 5 min (`eventOverrun`) shortens the wait to 15 s (`overrunEndAfter`) and the toast names the event: "„Budżet Q4” już się skończyło? Kończę notatki za 15 s." (only when some call app held the mic during this recording: a live meeting with no detected app never gets an end toast). The end toast keeps "Nagrywaj dalej"; the stop after 15 s is cancelled by the button, by the app taking the mic again, while another call of the same recording runs, and a manual stop in the countdown is final (`PendingStop` remembers the meeting id). Never records or stops without a visible prompt. The poll reads "Wykrywaj spotkania" every time and starts in `startServices()` (never in the design preview or the test host).

**Storage.** `AppPaths.meetings/<meetingID>/me.caf` and `them.caf`, never under `Recordings/` (the dictation orphan sweep would delete them). Rows: `Meeting` (title, status, duration, app name, notes and note lines, AI notes with template, model and error, speaker names, `hasAudio`, interruptions, transcript model / AI model / error, folded search text, `calendarEventID` and `participants` from the calendar event, stored as `participantsJSON`, "Zapytaj" questions and answers as `questionsJSON`) and `MeetingSegment` (track, start, end, text, word times, speaker, echo flag, `originalText` before an AI fix). Schema changes stay additive with defaults; `DatabaseMigrationTests` covers them. "Zachowuj nagrania spotkań" (Nie zachowuj, 7 dni, 30 dni, Zawsze) deletes only the audio folder and sets `hasAudio = false`; transcripts and notes stay. It sweeps at launch and after every finished meeting.

**Export.** Markdown (title, date, "Uczestnicy: Anna, Piotr" when the meeting has participants, notes, AI notes, transcript without echo) and an open JSON format `captylo.meeting.v1` (`MeetingExport.formatID`: ids, tracks, segments with word times, notes, AI notes, `participants`, `calendarEventID`), the format later devices and sync will read. A meeting with "Zapytaj" questions adds a "Pytania" section after the AI notes in Markdown (only answered questions; each question a `###` heading, the answer's headings two levels down) and the array `questions` in JSON (always present, failed ones too).

**Search (Free).** `MeetingSearchIndex` (`Meetings/Search/`) is our own SQLite file next to the store, `AppPaths.searchIndex` = `Search.sqlite` (WAL, `PRAGMA user_version` = `MeetingSearchIndex.version`, 1), never SwiftData's private schema: an FTS5 table `entries(body, meeting UNINDEXED, segment UNINDEXED, kind UNINDEXED, start UNINDEXED, track UNINDEXED)` on the `trigram` tokenizer, a `keys` table (segment id, or `title:` / `notes:` + meeting id, to the FTS rowid, so an upsert or a delete never scans the FTS table) and `meta` (`meetings` and `builtAt` of the last full build). One row per segment that is not echo plus a title row and a notes row per meeting (empty ones too, so the counts stay stable). The body is folded with `MeetingSearch.fold` before it is stored (the tokenizer's own folding keeps "ł"); the original text is never stored, snippets come from the store, so the index never holds anything the store does not. `SearchQuery.terms` folds the query, splits on anything that is not a letter or digit (quotes and FTS5 operators never reach the index), keeps words of 3+ characters and stems them crudely (a Polish case ending "-cie", "-ach", "-ami", "-ie", "-om", "-ow", "-em" is dropped first, then at most 6 characters: "budżecie" finds "budżet", "ofercie" finds "ofertę", "cenach" finds "ceny"; otherwise a 4-character word drops a final vowel, other words up to 4 stay, 5-7 lose the last character, longer keep their first 6: "cena" finds "ceny", "oferta" finds "ofertę", "ofert", "ofertą"; "zarzad" finds "Zarząd"; "lodz" finds "Łódź"; never under 3 characters); `match(_:all:)` quotes each term and joins them with AND (the list; all terms in one entry) or OR (the library ask). Ranking is bm25 weighted x2 for the title and x1.5 for the notes. `meetingHits` ranks per meeting in SQL (a window function: every matching meeting up to the limit with its best N segment lines plus title / notes), so one meeting that repeats a word hundreds of times never pushes the others out. A class with its own serial queue rather than an actor: the SQLite handle lives only on that queue, and the `MeetingIndexing` writes are synchronous calls that only enqueue, in the order of the store saves.
- **Sync.** `Database` gets the index in `init(modelContainer:searchIndex:)` (nil in tests that do not need it) and calls it after every successful save, never throwing back into the store path (failures are logged): `appendSegment` and `updateSegments` upsert the segments (a segment marked echo is removed), `replaceSegments` (cloud transcript), `restoreOriginalTranscript` and `markInterruptedMeetings` (launch recovery, echo marks) reindex the whole meeting, `deleteMeeting` removes it, `createMeeting` / `updateMeeting` / `modifyMeeting` reindex the title and notes rows.
- **Launch.** `startServices()` runs `prepare(database:)` detached at utility priority: it opens the file and rebuilds when the file is new, of another version, fails `PRAGMA quick_check` (a corrupt file is deleted and recreated) or when the meeting count or the count of non-echo segments differs from the store's (a crash lost writes). `rebuild(from:)` empties the tables and refills them one meeting per transaction, newest first; each meeting is read and queued in one step on the `Database` actor, so a save during the rebuild is never lost. It logs "Search index rebuilt: N meetings, M rows in X ms" (counts only). Until the index is ready (`isReady`), or when it cannot be opened (`.unavailable`), the list search uses the old `Database.meetings(query:limit:)` `contains` path over the folded search text, and so do queries with no word of 3+ characters.
- **Isolation.** Only the real store gets the real file: an overridden store (design preview, test host) and the in-memory fallback store get an in-memory index (`AppStateOverrides.searchIndexURL`), so neither can empty the real index.
- **UI.** `MeetingsView` with a query that has terms calls `MeetingSearchResults.load` (`@concurrent`, off the main actor): `meetingHits` (AND, up to 200 meetings, 2 segment lines each), then `Database.meetings(ids:)` and `segments(ids:)`, ordered by best rank, newest on ties; under the search field "N spotkań". Each row shows up to two hit lines (`MeetingSearchHitsView`: `[12:34]`, the speaker, a snippet of about 80 characters cut on word boundaries with the matched words bold, built by `MeetingSearchSnippet` from the store's text), plus a "Notatki: ..." line when the notes matched and there is room. A click selects the meeting and opens "Transkrypt" scrolled to the line holding that segment (merged lines included) with a 1.5 s Tide highlight (`MeetingTranscriptJump`), or opens "Notatki" for a notes hit. Measured on a Debug build with 200 meetings x 600 segments (120k rows): 6-34 ms per query, 82 ms for a word in a third of the rows.

**Zapytaj.** Both asks go through `MeetingChat` on `HTTP.meetingLLMSession` on the features model (`MeetingAITask.ask` / `.libraryAsk`), `maxTokens` 1500, questions cut to 1000 characters, with `MeetingPrompts.askSystem` / `libraryAskSystem` as the instructions and `askReminder` / `libraryAskReminder` closing the data; answers go through `CitationNormalizer`. A single meeting whose data does not fit the 20k-token input budget (`TranscriptChunker.fits`) gets a plain Polish message instead of a call (no split path for "Zapytaj" yet). Without an AI route the answer is the reason with "Otwórz Modele"; the design preview never calls the network. Measured with Minitron: 2-19 s.
- **One meeting** (the fourth tab "Zapytaj" in the details, `MeetingAskView`): `MeetingAsker.ask(meetingID:question:)` sends `MeetingAITask.ask` with `MeetingAskPrompt.user` (title, date, participants, the user's notes, the transcript as `[mm:ss] Label: text` lines without echo, the last 3 answered questions, the question). The answer cites `[mm:ss]` and is exactly "Nie znalazłem tego w tym spotkaniu." / "I couldn't find that in this meeting." (`MeetingAskPrompt.notFound`, quoted by the instructions) when the meeting has no answer. The result (answer, model or a Polish error) is stored on the row as `Meeting.questionsJSON` (`MeetingRecord.questions: [MeetingQuestion]`, newest last, at most 50) in one `modifyMeeting` step. No call, but a stored error, while the meeting records or when it has fewer than 5 words. `MeetingAskRuns` (`@MainActor @Observable`, owned by `AppState`) tracks the runs per meeting, so switching meetings mid-answer is fine. Answers render with `MeetingNotesSections` like the AI notes; citations play the recording.
- **All meetings** ("Zapytaj wszystkie" next to the search field, `LibraryAskPanel` sheet): `LibraryAsker.context(question:)` retrieves before any AI call. Terms are `SearchQuery.terms` minus Polish and English stopwords and time words (`LibraryAskRetrieval`), matched with OR through `meetingHits` (24 candidate meetings, 12 best lines each, plus title / notes); the 8 best meetings by the sum of their hit ranks (newer wins ties) each send their hit lines with one neighbor before and after (merged when adjacent), title, date, participants, the first 600 characters of the AI notes, and the start of the user's notes when they matched. A question about time ("ostatnio", "wczoraj", "w zeszłym tygodniu", "miesiąc temu", this or last week / month, the last 7 / 30 days, `LibraryAskRetrieval.period`; a week or month counts only with a qualifier next to it, so "Ile kosztuje miesiąc licencji?" or "za tydzień" stays a topic search over all dates) or with no topic words picks meetings of that period by date (`Database.meetings(createdIn:limit:)`, topic hits first), sending the AI notes (2000 characters) and the 12 closing lines of those without hits. No hits, or no meeting in the period: "Nie znalazłem tego w spotkaniach." without calling the AI. Index not ready: the 8 newest meetings with AI notes (2000 characters each), with the line "Szukam tylko w notatkach AI, indeks się buduje." above the answer. `LibraryAskPrompt.user` numbers the meetings `S1...S8` with a header line (title, date and time, participants) and puts the current date in the data; the `library_ask` answer cites `[S1 12:34]`; `LibraryCitation.parse` turns `[S1 12:34]`, `[S1, 12:34]`, `[S1 1:02:03]` and `[S1]` into links to a real source, and an unknown `S9` or a malformed stamp stays plain text. A citation or a "Źródła" row closes the panel, selects the meeting (pulled in even when it is older than the list or hidden by the search, `MeetingListSelection`) and jumps in "Transkrypt" to the line at that second (`MeetingCitations.segment`) like a search hit. The session keeps the last 5 exchanges in `MeetingAskRuns` while the app runs; they are never stored.
- **What leaves the Mac.** On the local model, nothing. With "Bielik w chmurze" on: one meeting sends that meeting's transcript, notes, title, date and participants to CloudFerro; all meetings send excerpts only (at most 8 meetings x 12 hit lines with neighbors), never whole transcripts. Questions and answers are never logged.

**MCP (Free, off by default).** A local, read-only [Model Context Protocol](https://modelcontextprotocol.io) server, so the user's own AI assistant (Claude Desktop, Cursor, ...) can list, read and search the meetings and notes on this Mac. The assistant starts it as `Captylo --mcp` and keeps the process for its session; Captylo itself does not need to run.
- **Setting.** "Dostęp dla asystentów AI (MCP)" in Ustawienia > Spotkania (`MCPSettingsRow`, `AppSettings.meetingsMCP`, key `meetings.mcp`, default off). On, it shows "Skopiuj konfigurację", which copies `{"mcpServers": {"captylo": {"command": "<this binary>", "args": ["--mcp"]}}}` (pretty JSON, `MCPSettingsRow.configuration`) and a caption where to paste it. The server reads the setting from `UserDefaults.standard` (the app's domain) at every call: off, `tools/list` is empty and a known tool returns `isError` with "Włącz dostęp w Captylo: Ustawienia > Spotkania > Dostęp dla asystentów AI (MCP)."
- **Mode.** `CaptyloMain` (`@main`) handles `--mcp` before AppKit or SwiftUI start: no `NSApplication`, no `AppState`, no services, no menu bar item, no LaunchServices check-in (a checked-in process would take every later launch of Captylo from Finder, the Dock or the login item). `MCPStandardIO` claims stdout first: the real stdout is duplicated to a private descriptor that carries only JSON-RPC lines, and descriptor 1 goes to stderr, so nothing else can ever reach the protocol; SIGPIPE is ignored. The process exits when the client closes stdin.
- **Protocol.** `MCPServer`: newline-delimited JSON-RPC 2.0, requests handled one at a time, one line per response. `initialize` (the client's protocol version when it is 2025-06-18, 2025-03-26 or 2024-11-05, else 2025-06-18; `serverInfo` "captylo" with the bundle version; capability `tools`; short `instructions`), notifications ignored, `ping`, `tools/list`, `tools/call`; unknown method -32601, malformed JSON -32700, not a request or a batch -32600, unknown tool -32602, unreadable store -32603. Ids are echoed as sent (numbers stay numbers, `JSONValue`).
- **Tools** (`MCPTools`, JSON Schema inputs with `readOnlyHint` annotations, Markdown text results, descriptions in English for the assistant's model, result texts localized): `list_meetings {query?, since? (ISO date), limit? <= 50, default 20}` (one line per meeting: date and time, title, length, app, id; a query goes through the index, then `contains`), `get_meeting {id, transcript? = true}` (`MeetingExport.markdown(includeTranscript:)`, with participants and "Pytania"), `search_meetings {query, limit? <= 30 meetings, default 10}` (title, date, `[12:34] Speaker: ...snippet...` up to 2 lines per meeting, id; the index, or the store's `contains` when it is missing, building or the query is shorter than 3 characters; then up to 5 matching notes as `- Notatka: Tytuł (data) · note id: ...`), `list_notes {query?, since?, limit?}` (one line per note: date and time, title or first line, `nagranie m:ss` for a voice note, id; a query goes through `noteHits`, then `contains`) and `get_note {id}` (Markdown: title, date and recording length, the text). Bad arguments come back as `isError` results.
- **Read-only.** `MeetingLibraryReader` opens `AppPaths.store` with `Store.openReadOnlyContainer` (`allowsSave: false`, same schema): a store of another schema fails to open (the MCP process never migrates; the error asks to start Captylo once) and a missing store creates nothing. The index is opened with `SQLITE_OPEN_READONLY` (`MeetingSearchIndex(url:readOnly:)`) and answers only with the current version and a finished full build (`meta.meetings`, which a rebuild clears first and sets last). SQLite cannot open a WAL database read-only without its `-wal` file, so the reader creates an empty one when it is missing (`O_CREAT | O_EXCL`, an existing one is never touched); besides the `-shm` SQLite creates for any WAL reader, that is the only file the MCP process may create, and the databases themselves are never written. Both are reopened when the file or its `-wal` changed (modification date, size, inode), so a meeting saved by the running app shows up without restarting the assistant. SQLite WAL readers and the app's writer coexist safely. No AI calls and no network from this mode; the log gets only start, stop and failures (tool name and error type, never arguments or meeting text).
- **Privacy.** The server sends nothing anywhere: it answers the process that started it. Where the meeting text goes next is decided by the assistant the user connected.

**Clocks.** `MeetingTime.clock` renders `12:34` under an hour and `1:02:03` from one hour; the list, the details, the live bar and the capsule player (`AudioPlayerView.clock`, seconds truncated, not rounded) all use it, so a two-hour meeting never reads `125:00`.

**No plans.** Every feature is available to everyone; the AI ones work whenever an AI route exists (`AIRouteProviding`), and say why when there is none.

**Echo reduction (experimental).** "Redukcja echa (eksperymentalna)" in Ustawienia > Spotkania (`AppSettings.meetingsVoiceProcessing`, off by default) asks the meeting mic's input node for Apple's voice processing (`setVoiceProcessingEnabled(true)` with other-audio ducking at its minimum, `VoiceProcessingSetup`) before the tap is installed; the converter takes the changed native format and the feed still gets 16 kHz mono. An input that refuses it (some Bluetooth outputs, error -10875, at enable or at `engine.start()`) gets the plain engine and the recording always starts; `MeetingMicCapture.isVoiceProcessingActive` says what runs, and `Log.audio` prints "Meeting mic voice processing: on / off / unavailable (...)" once per start and again only when a rebuild (device change, wake) changes the outcome. Read at the meeting's start, so a change applies from the next meeting. `EchoFilter` stays as the second line. Open question for the field: whether VPIO's echo reference on macOS covers other apps' output (Zoom, Meet) or only what Captylo plays.

**Debug.** `--meeting-from-files <me-audio> <them-audio>` runs the pipeline on two files without the mic or the tap and reports the process peak memory; `--benchmark <audio>` runs the local model on one file with timings, peak memory and the word error rate (see the debug flags below). `PeakMemory` reads `task_info` `TASK_VM_INFO` (`phys_footprint` now, `ledger_phys_footprint_peak` since launch, through `task_self_trap()` because the global `mach_task_self_` does not pass Swift 6).

**Known limits.** Echo without headphones is removed from the transcript (`EchoFilter`, 3+ words that mostly repeat an overlapping "Rozmówcy" segment), not cancelled acoustically; short replies like "tak" are kept on purpose. A mic segment that only partly repeats the other side loses those runs of 4+ words heard on "Rozmówcy" within 1.5 s (word times), and keeps the user's own words: on the owner's meeting this removed 21 duplicated words without losing any (WER 31.4 % to 30.1 %). The HAL zero-buffer bug is handled by rebuilding the tap, which can leave a short gap. Browser meetings are detected only with the Accessibility grant and a call service in a window or tab title; Arc exposes no readable tab strip, so an Arc call ends only when the mic is released or the app quits. Slack huddles and FaceTime have no reliable title, so their mic use alone is the signal, and FaceTime audio may run in a system daemon the catalog does not see. The calendar only helps a recording that starts within an event's window; an event without a call link is matched but never reminded about, and the calendar-based end needs a detected call app. Voice processing is a switch, not a promise: outputs that refuse it fall back silently. Diarization needs macOS 15+.

## Notatki

The third pillar next to dictation and meetings (sidebar section `notatki`, `NotesView`), Free and local. A note is typed, dictated or recorded: a voice note is simply a note with audio.

**Data.** `@Model Note` (`Data/NoteModels.swift`, value mirror `NoteRecord`): title (empty = the list shows the first line, `displayTitle`), body, `originalBody` (the text from before the first AI pass), `audioFileName` under `AppPaths.notes` (`Notes/<id>.wav`, never under `Recordings/`, which the dictation orphan sweep cleans), duration, language, transcript model and error, AI mode, folded `searchText`. All writes go through `Database+Notes` (`createNote`, `updateNote`, `modifyNote` in one actor step, `deleteNote` returning the audio file name).

**Ready for sync (M7).** `Note`, `Meeting` and `Dictation` carry `updatedAt` and `deviceID`, stamped by every write (`touch()`); `DeviceIdentity` keeps one id per installation in `device.json` in the data folder, loaded by `startServices()` (empty in the test host and MCP). Deletes stay hard, but every delete of a note, meeting or dictation writes a `Tombstone` (`kind`, `entityID`, `deletedAt`, `deviceID`) in the same save. Never name a stored property `entity`: it collides with `NSManagedObject.entity` and crashes on insert.

**Takes for notes.** `DictationController.start(destination:)` takes `TakeDestination.paste` (the hotkey, as before), `.newNote` (⌃⌥⇧N, `GlobalShortcut.note`, setting `notes.shortcut`, menu bar "Nowa notatka głosowa", press to start and again to stop; `TakeDestination.forShortcutPress` stops a running dictation as a dictation) or `.appendToNote(id)` ("Dyktuj" in a note). A note take runs capture, transcription, spelling and the dictionary like a dictation, then skips the AI, the paste, the history row and the word count: a new voice note moves its WAV to `Notes/` (`NoteTake.adoptAudio`) and shows "Zapisano notatkę" with "Otwórz" (`WindowPresenter.openNote`), an append adds a paragraph. A failed transcription keeps the voice note with its audio and `transcriptError` ("Spróbuj ponownie" = `NoteActions.retryTranscription`). `RecorderCoordinator` keeps a plain `start()`.

**Import.** "Importuj nagranie" (and audio dropped on Notatki) feeds `AppState.noteImportQueue`, a second `FileTranscriptionQueue` built with `Services.makeForNotes`: WAVs under `Notes/`, `NoteRecord.imported(from:)` per file, no AI, nothing in Historia, kept with history off.

**AI.** "Uporządkuj przez AI" (`NoteActions.applyAI`) runs the body through a dictation AI mode on the features model (`AIRole.features`, the prompt from the app), keeps the user's text in `originalBody` once ("Przywróć oryginał"), never writes errors into the body.

**Titles.** The list shows the stored title, else the first sentence cut to 6 words (`NoteTitles.local`, derived live in `displayTitle`, never stored, so it follows the text). An AI title is stored once (`NoteActions.ensureTitle`) only with "AI" on in dictation (`AppSettings.aiEnabled`, the user's consent to send dictations to the AI) and at least 5 words: after a voice note or a dictated paragraph is saved, after an import is transcribed, after a retried transcription (in the background) and when the user leaves a note edited during the visit (browsing costs no call). The correction model (`AIRole.correction`) writes 2-6 words (`NoteTitles.job`, a `rewrite` job, prompt from the app, first 4 000 characters); two triggers at once make one call; a title typed meanwhile is never overwritten. Leaving an untouched empty note deletes it (no tombstone), except while a dictation into it is on its way or its text is unsaved; an append whose note is gone becomes a new note.

**Editor.** `NoteDraft` saves after a 0.6 s pause and when the note is left, through `modifyNote`, writing only the fields edited since the last save (`NoteDraft.Change`), so a title written elsewhere (the AI title) is never overwritten by the draft's stale copy; a failed save stays unsaved and is tried again. While something else writes the open note (an AI pass, a retried transcription, "Dyktuj" into it) the title and text are read-only, and the draft is saved before each of them starts. `applyAI` replaces the body only if it is still the text the AI was given (else "Notatka zmieniła się w trakcie..."); a retried transcription is added under text typed meanwhile. `AppState.notesVersion` (`notesTicker`) makes the list and the open note reload after changes made elsewhere; a reload keeps the draft when it still shows the stored text or holds unsaved keystrokes.

**Search.** Notes share `Search.sqlite` (version 2): rows of kind `noteTitle` / `noteBody` with the note id in the `meeting` column; every meeting query filters `kind IN ('title', 'notes', 'segment')`. `noteHits(terms:all:limit:)` ranks notes through a `MATERIALIZED` CTE (FTS5 refuses `bm25` inside an aggregate). Notatki searches notes; Spotkania shows up to five matching notes under its header ("Także w notatkach", `NoteMatchesStrip`). "Zapytaj wszystkie spotkania" also sends up to 5 matching notes (`noteHits` with any term, or the newest of the period for a question about time) as `<notes>` `N1...` after the meetings, cut to 1 500 characters each; `[N1]` citations (`LibraryCitation.Kind.note`) open the note and "Źródła" lists them. The `libraryAsk` instructions (`MeetingAIInstructions`) describe `<notes>`. The MCP server has `list_notes` and `get_note`, and `search_meetings` lists matching notes (see "MCP").

## Debug CLI flags (kept in Release, documented for support)

Run `Captylo.app/Contents/MacOS/Captylo <flag>`; the app runs headless, prints JSON to stdout and exits:

- `--transcribe <audio file> [<audio file>...] [--ai] [--mode <key|name>] [--language pl] [--engine local]` - full pipeline without the mic (decode → engine → spelling → text processing → optional AI). Several files run one after another in the same process, one JSON object per file (with `"file"`): the first meets a cold model server, the next ones a warm one, like dictations in a row. `--mode` picks the AI mode for this run only (a built-in key such as `cleanup`, `email`, `tasks`, `organize`, `english`, or a mode's name, case and diacritics ignored), implies `--ai` and never changes the setting; an unknown mode prints `{"error", "modes"}`. `--engine` accepts only the local engine (`local`, also `whisper` or `parakeet`; anything else fails to parse, never reads the Keychain without `--ai`); the local model is loaded before the pass, so `transcriptionMs` is the pass alone. Output: `{"text","rawText","spelled","enhancedText","modelName","transcriptionMs","enhancementMs"}`; nothing is learned from a debug run.
- `--meeting-from-files <me-audio> <them-audio>` - the meeting pipeline without the mic or the system audio tap (no TCC): both files are decoded to 16 kHz mono and fed from meeting time 0 in 4096-sample chunks, alternately, into a real `MeetingTranscriber` (the app's Whisper engine, Silero VAD, echo marks at the end) that saves into an in-memory store. Uses the transcription language setting; the model must be downloaded. On macOS 15+ it then labels the speakers of the `them` file like after a real meeting (the offline diarizer downloads its models on first use). Output: `{"ok": true, "segments": [{"track": "me", "start": 1.2, "end": 3.4, "text": "...", "echo": false, "speaker": null}], "transcribed", "language", "speakerTurns", "voices", "ms", "peakMemoryMB"}` (segments as stored, in transcript order; `transcribed` differs from their count only when a save failed; `speakerTurns` and `voices` are null when no diarization ran, and `speaker` stays null with fewer than two voices; `peakMemoryMB` is the process peak footprint, the number to watch in a 2 h soak), or `{"ok": false, "error"}`.
- `--meeting-ai <transcript.json> [--template <id>] [--fix] [--ask <question>]...` - the AI after a meeting on a saved transcript, in an in-memory store and on the app's AI routes (local Bielik or "Bielik w chmurze", as set): the transcript fixes with `--fix` (`MeetingTranscriptCorrector`, the correction model), the AI notes (`MeetingSummarizer`, the features model, in parts with merges when the meeting is over the input budget) and "Zapytaj" (`MeetingAsker`) once per `--ask`, later questions seeing the earlier answers. The input (`DebugMeetingInput`) is the JSON `--meeting-from-files` prints, optionally with `title`, `participants` and `speakerNames` (`{"1": "Agnieszka"}`); a segment needs `start` and `text`, `track` defaults to `them` and a missing `end` runs to just before the next segment. `--template` takes a `BuiltInMeetingTemplates` id (default: picked from the title, like a meeting). Output: `{"ok": true, "title", "segments", "words", "durationSeconds", "fix": {"model", "changed", "changes": [{"start", "before", "after"}], "ms"}, "notes": {"template", "model", "calls", "markdown", "ms"}, "ask": [{"question", "answer", "error", "model", "ms"}], "ms", "peakMemoryMB"}` (`fix` and `ask` only when asked for; a failed question carries its `error` and does not fail the run), or `{"ok": false, "error", "ms"}`. The F3 measurements (`docs/benchmark.md`) use it with `-ai.enabled YES` appended, a defaults-domain argument that turns the AI on for that process only.
- `--benchmark <audio file> [--reference <txt file>] [--language pl]` - the owner's accuracy and speed check: transcribes the whole file with the app's local engine (the installed Whisper model; long files are cut at pauses into 30 s windows). `--language` works like `--transcribe` (default: the transcription language setting). Output: `{"ok": true, "file", "durationSeconds", "language", "reference": <bool>, "model", "text", "loadMs", "ms", "rtf", "peakMemoryMB", "memoryDeltaMB", "wer": {"percent", "substitutions", "deletions", "insertions", "words"} | null}`. `wer` (`WordErrorRate`, word Levenshtein on folded, punctuation-free tokens) needs `--reference`; `loadMs` includes the Neural Engine compile on the first load of a model; `peakMemoryMB` is sampled every 100 ms while the model loads and runs. A language code outside the picker list fails instead of running as auto.
- `--watch-paste <text>` - hidden self-learning check: pastes the text into the focused field like a dictation, watches it like after a dictation and prints the learning memory when the watch ends. Run it with `CAPTYLO_DATA_DIR=<scratch folder>` so the lessons land there.
- `--show-widget <recording|transcribing|enhancing>` - shows the widget with fake levels and sample live text and stays up until killed (for screenshots with `screencapture -x`).
- `--check` - prints permission states, model status, selected device, hotkey, the data paths, the active AI mode, "Bielik w chmurze" (on, model, whether a key is saved; never the key), the history row count and `localAI` (the llama-server helper, the tier and memory budget, each Bielik model on disk, the models folder, per role the pick, where it runs and its server state; no server is started), with no network. It reads the Keychain, so an ad-hoc Debug build can block on an ACL prompt. `--transcribe --ai` prewarms the cleanup model's server while it transcribes, like the hotkey does, and every headless run stops the model servers before it exits. A manual check against the real models: `CAPTYLO_DATA_DIR=<scratch>` with `LocalModels` symlinked to a folder that holds the GGUF files (and `WhisperModels` to an installed Whisper model); a debug run on the real data folder shares its pid files with a running app, whose servers its start would stop.

- `--rebuild-search-index` - empties the meeting search index (`Search.sqlite` next to the store) and fills it again from the store this run opened, like a launch that found it out of step. Refuses the in-memory fallback store (it would empty the index). Output: `{"ok": true, "file", "meetings", "rows", "ms"}` or `{"ok": false, "error"}`. Use `CAPTYLO_DATA_DIR` with a copy of the store for checks; it migrates that store like a normal launch.
- `--mcp` - the read-only MCP server (see "MCP" under Spotkania) on stdin/stdout for an AI assistant; not a support tool. Handled by `CaptyloMain` before AppKit starts, runs until the client closes stdin, prints nothing but JSON-RPC lines on stdout. Reads the store and the index at `AppPaths` read-only, so `CAPTYLO_DATA_DIR=<copy>` for manual checks; `-meetings.mcp YES` on the command line turns the setting on for that run only (argument domain), without touching the real defaults.

`CAPTYLO_DATA_DIR=<folder>` points `AppPaths` (store, search index, dictionary, recordings, meetings) at another folder for support and for migration checks on a copy of the store. Settings still come from the real defaults domain.
- `--reset-onboarding` - clears onboarding progress.
- `--ax-probe [--show-text]` - hidden self-learning spike tool: once a second prints a one-line JSON when the focused text field changes (bundle id, role, subrole, length, readable, selection). Sets `AXManualAccessibility` once per frontmost app so Electron apps expose their fields. The field text (last 80 characters) is printed only with `--show-text`. Runs until killed; needs the Accessibility grant. Findings go to [docs/reference/ax-coverage.md](reference/ax-coverage.md).
- `--open-section <pulpit|spotkania|notatki|historia|plik|slownik|modele|ustawienia>` - hidden screenshot helper: a normal GUI launch (services, tap, menu bar) that skips the onboarding and opens the main window on that section.
- `--design-preview <target>` - hidden design helper: one screen (widget state, onboarding step, main section, `glass-gallery` or the `popraw` panel) on fake services built through `AppStateOverrides` (in-memory store with sample history and three sample meetings, defaults suite `pl.craftweb.szpak.design-preview` wiped at start, temp dictionary, seeded key store, pinned local model "ready", a pinned "ready" voice detector, Accessibility, and a `FixedCalendarSource` that is empty unless `CAPTYLO_PREVIEW_CALENDAR=1` seeds three invented events; EventKit is never created; an in-memory search index; "Zapytaj" never calls the network). Spotkania also reads `CAPTYLO_PREVIEW_TAB=notes|transcript|ai|ask`, `CAPTYLO_PREVIEW_QUERY=<q>` (the search field opens with `q` typed, e.g. `oferta`), `CAPTYLO_PREVIEW_HIT=1` (with a query: the first hit line clicked) and `CAPTYLO_PREVIEW_ASK_ALL=1` (the "Zapytaj wszystkie spotkania" panel with a seeded answer); the full list is in `scripts/snap.sh`. No services, no hotkey tap, no menu bar item, never activates the app. Prints `WINDOW_FRAME=x,y,w,h` and `WINDOW_ID=<n>` when the window is up (optional `CAPTYLO_PREVIEW_BACKDROP=white|dark|<image>` puts a backdrop window behind it) and runs until killed; unknown target = JSON error, exit 64. Driven by `scripts/snap.sh <target> <out.png>` (see dusk-glass.md).

When the app is the unit-test host (`XCTestConfigurationFilePath` set) it skips `startServices()` and the onboarding, so `make test` never installs a second hotkey tap. It builds `AppState` on `AppStateOverrides.testHost()` (in-memory store and search index, temp dictionary, wiped `pl.craftweb.szpak.test-host` defaults suite), so a schema change can never migrate the user's store while a real Captylo is running.

Schema changes stay additive and optional (or defaulted), so SwiftData migrates the store in place without a `VersionedSchema`; `DatabaseMigrationTests` keeps a frozen copy of the previous schema and checks both the upgrade and a rollback to it.

## Build and install

`make gen` (XcodeGen), `make build` (Debug, `.local-build/`), `make test`, `make release` (Release, re-signed inside-out with Captylo Dev or ad-hoc through `scripts/sign-app.sh`, copied to `~/Downloads/Szpak.app`), `make install` (also copies to `/Applications`), `make check` (Debug binary `--check`), `make reset-tcc` (resets the `pl.craftweb.szpak` grants). Heavy commands on the shared build Mac go through the lock: `lockf -k /Users/dawid/clienty/captylo-bielik-local/heavy.lock make build`. The first load of the local model compiles it for the Neural Engine (2-3 min, once per model, cached by Core ML); later loads ~0.3 s.

Public releases ([release.md](release.md)): `make dist VERSION=x.y.z` builds Release with `CFBundleVersion` = `git rev-list --count HEAD`, signs with Developer ID, notarizes, staples and packages `dist/<version>/Szpak-<version>.dmg` (hdiutil, UDZO, an Applications shortcut). There is no appcast and no upload: the DMG goes to a GitHub release by hand, with the owner's go-ahead. `dist/` is git-ignored.
